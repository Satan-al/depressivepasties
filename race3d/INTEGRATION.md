# Гонки 3D — установка

1. Распакуйте архив.
2. Откройте корень репозитория Satan-al/depressivepasties, ветку main.
3. Через Add file → Upload files загрузите одновременно index.html и папку race3d из архива. Нужна именно папка со всеми файлами внутри, не один HTML.
4. Сохраните одним коммитом, дождитесь обычного деплоя.
5. Всем обновить страницу; оверлей Python перезапустить.
6. Обычная кнопка гонок открывает лобби. Создатель выбирает Виталика/Вадю и нажимает «Старт», остальные — «Вписаться».

Цвета берутся из профилей. Подписей игроков у машин нет. Каждый участник видит свою машинку; оверлей с профилем Лёхи — его машинку. Если профиль открыт одновременно на сайте и в оверлее, управляет окно, из которого вступили в заезд. Второе окно только наблюдает.

Создатель заезда считает всю физику, ботов, события и результаты; остальные отправляют управление. Не сворачивайте окно создателя во время теста: браузер может притормозить его работу в фоне. Если ведущий пропадает, показывается сообщение, затем заезд завершается. Автоматической передачи роли ведущего пока нет.

WASD / стрелки — ехать; пробел — дрифт; R — вернуть машину на трассу. Время заезда — до трёх минут, три круга. До 12 игроков и два бота.

Правила Firebase из текущего репозитория уже разрешают существующим участникам запись в games. Новые пути: games/active (только лобби и фазы) и games/race3d/<id> (управление и снимки гонки). Новые ключи, аккаунты и ручной обмен кодами не нужны. Бот и Python не изменялись.

Проверено: синтаксис основного index.html и модулей, независимое управление игроками, частота всех событий, лобби/состав/старт, проверка источника сообщений iframe. Реальный заезд с двух устройств и производительность в Qt-оверлее ещё требуют проверки вами. Клиент получает общую физику с интерполяцией, поэтому задержка управления зависит от связи с Firebase.

Архив подготовлен на основе коммита 3a02230076fa4e0fc593ab746fb2984cc837f378. GitHub отказал интеграции в записи (403); автоматически на действующий сайт ничего не опубликовано.

Откат: вернуть предыдущий index.html через историю GitHub. Старый движок остаётся в предыдущей версии; данные профилей, бот и другие игры не менялись.

## Исправление задержек, v2
Загрузить index.html и папку race3d вместе, затем всем обновить страницу и перезапустить оверлей. WebRTC автоматически использует Firebase для знакомства браузеров; если прямое соединение недоступно, продолжается обмен через Firebase. Ведущий передаёт прямые снимки около 30 раз/с, резервные — до 12 раз/с. Управление своей машиной прогнозируется локально и сверяется с ведущим. Неподтверждённые последние команды повторяются; отпускание кнопок больше не пропускается из-за занятой записи.
Реальный тест на двух устройствах после этой правки ещё не проведён. Отдельные ошибки meshcast /whep 404 относятся к видеопотоку; его код в обновлении не менялся.

## Производительность, v3

Загрузить index.html и всю папку race3d одним коммитом. После деплоя всем обновить страницу, оверлей перезапустить.

- Неподвижная геометрия объединяется по материалам: сохраняются размеры, положения, текстуры и анимированные части. Машины также собираются в меньшее число групп отрисовки.
- Клиент обрабатывает только последнее полученное состояние один раз за кадр, вместо повторного пересчёта для всех пакетов, пришедших между кадрами.
- Поиск ближайшего участка дороги использует квадраты расстояний; результат проверен сравнением с прежней формулой.
- Начальное разрешение теней снижено с 2048 до 1024; максимальный коэффициент разрешения рендера — с 1.6 до 1.25.
- Кнопка «Графика» переключает обычный/лёгкий/минимальный режим. При устойчивом FPS ниже 30 режим автоматически облегчается. Лёгкий отключает динамические тени, минимальный дополнительно снижает разрешение. Под машинками остаются простые тени. Геометрия машин, локации, события и частота физики сохраняются.
- FPS измеряется по настоящему времени между кадрами, а не по ограниченному шагу симуляции.
- Таблица мест обновляет разметку только при изменении содержимого.

Для диагностики во время гонки: в основной консоли (контекст top) выполнить window.__raceStats(). Возвращаются роль, канал связи, FPS, режим графики, число вызовов отрисовки и время обработки последнего кадра. frameWorkMs включает код кадра и отправку команд рендереру, но не является прямым измерением времени GPU.

Проверки: совпадение ближайших участков на 3000 точках; сохранение границ геометрии при объединении; сохранение анимаций и освобождения ресурсов в пяти локациях; инициализация окна игры, один пересчёт состояния за кадр и автоматический режим графики с имитацией рендера. Реальный FPS на устройстве игрока в этой среде не измерен.
